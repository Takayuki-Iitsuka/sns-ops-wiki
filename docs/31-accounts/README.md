# 運用アカウント台帳

> **このページで分かること**: 運用しているアカウントの**公開情報だけ**を記録する台帳の書き方。何を書いてよいか、何を書いてはいけないか、記入例。
>
> **対象**: 初心者(このリポジトリに記録する人)  **先に読むページ**: [CONTRIBUTING](../../CONTRIBUTING.md)、[目標・KPI](../30-strategy/01-goals-kpi-roadmap.md)
>
> **最終確認**: 2026年(皇紀2686年・令和8年)11月3日。表の中の年は西暦のみで表記します。

このナレッジベースを使って運用するアカウントの**公開情報**だけを記録します。題材ごとの内容(題材別の企画・用語など)は別の wiki で管理します。

## 概要

台帳は「どのサービスで、どのアカウントを、どんな状態で運用しているか」を一目で分かるようにする表です。複数のサービスを運用すると、「どこにアカウントがあるか」「どれを休止中か」を忘れがちです。台帳があると、プロフィールの表記をそろえるときや、なりすましを見つけたときに役立ちます。

このリポジトリは **public(誰でも見られる)** です。そのため、ここに書くのは**誰でもプロフィールを開けば分かる情報だけ**にします。数字や認証情報は、非公開の表計算などで管理します。

## 用語

| 用語 | 意味 |
|---|---|
| handle(ハンドル、ユーザー名) | `@` から始まるアカウントの ID。URL に使われる |
| display name(表示名) | プロフィールに表示される名前。後から変えやすい |
| public information(公開情報) | ログインしなくても、誰でも見られる情報 |
| 桁・帯 | 実数の代わりに使う大まかな範囲。例: 「3桁」「1,000人台」 |

### 記入方法

1. **アカウント**: ハンドル(`@` を除いた ID)を書きます。未作成なら「(未作成)」。
2. **サービス**: X、Instagram、note、YouTube、TikTok、Threads など。
3. **URL**: プロフィールの URL。未作成なら「—」。
4. **状態**: 下の「状態の定義」から1つ選びます。
5. 変更したら、このページの「変更履歴」に日付と内容を1行追加します。

### 状態の定義

| 状態 | 意味 |
|---|---|
| 検討 | 開設するか検討中 |
| 予定 | 開設を決めたが、まだ作っていない |
| 準備中 | 作成済みで、プロフィール整備やストック作りの段階(未公開投稿のみ) |
| 運用中 | 定期的に投稿している |
| 休止中 | 一時的に投稿を止めている(休止告知の有無をメモ) |
| 終了 | 運用をやめた(削除済みかどうかもメモ) |

### 各項目の書き方

| 項目 | 書き方 | 記入例(架空) |
|---|---|---|
| 開設時期 | 年月まで(日付は不要) | 2026年4月 |
| フォロワー帯(桁) | 実数ではなく桁か帯 | 3桁 / 1,000人台 |
| 強い投稿の型 | 反応が良い投稿の形式・構成 | 手順を5枚で見せるカルーセル |
| 弱い点 | 改善したいこと | リンククリックが少ない |
| 運用に使える時間(週) | 時間の目安 | 3〜5時間 |

- 年は本文中で書く場合、「2026年(皇紀2686年・令和8年)」の形式で併記します(表の中は「2026年4月」のような短い表記で構いません)。
- 更新は**四半期に1回**程度で十分です([目標・KPI](../30-strategy/01-goals-kpi-roadmap.md) の四半期見直しと合わせる)。

## 書いてよいもの / 書いてはいけないもの

| 書いてよい(公開情報) | 書いてはいけない |
|---|---|
| ハンドル、プロフィール URL | パスワード、2段階認証のコード・バックアップコード |
| サービス名、運用状態 | API キー、アクセストークン(`YOUR_API_KEY` のような例示のみ可) |
| 開設時期(年月) | ログイン用のメールアドレス・電話番号 |
| フォロワーの桁・帯、投稿の傾向 | フォロワー・売上などの実数、非公開のインサイト |
| 公開しているリンク先 | 本名・住所など、プロフィールで公開していない個人情報 |

## 台帳(非公開で管理するもの)

- 投稿計画と結果(数値)
- 画像・フォントの権利台帳([image-sources-and-copyright](../01-common/image-sources-and-copyright.md))
- 収益・経費の帳簿([tax-and-business](../30-strategy/04-tax-and-business.md))
- API の鍵・トークン(**絶対にここに書かない**)

> パスワード・2段階認証コード・非公開の数値は**ここに書かない**(public リポジトリ)。

## よくある失敗と対処

| 失敗 | 対処 |
|---|---|
| 「ちょっとだけなら」と実数を書く | 桁・帯に置き換える。書いてしまったら削除し、履歴にも残る点に注意(公開リポジトリの履歴は消しにくい) |
| ハンドルを変えたのに台帳を直さない | 変更したらすぐ台帳と変更履歴を更新 |
| 休止中のアカウントを放置 | 状態を「休止中」にし、プロフィールに休止の告知を書く。乗っ取り対策の確認も続ける([アカウントの安全](../01-common/account-security.md)) |
