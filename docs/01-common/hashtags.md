# ハッシュタグ設計(共通原則)

> サービスごとの上限・推奨数は各 `04-text-hashtags.md` を参照(多くが要確認)。

## 役割

| 役割 | 例 | 目的 |
|---|---|---|
| 分類タグ | `#サンプル運用記録` | 自分の投稿を束ねる(自社タグ) |
| 話題タグ | `#SNS運用` | 検索流入 |
| 固有タグ | `#ブランド名` | 指名検索・ファン形成 |
| イベントタグ | `#○○フェス2026` | 時事・イベント参加 |

## 設計手順

1. 目的を決める(発見されたい / 集めたい / イベント参加)。
2. 候補を10〜20個出し、各タグの投稿の質・量・鮮度を実際に検索して確認する。
3. 「大(数百万)・中(数万〜数十万)・小(数千)」を混ぜ、**関連性が高いものだけ**残す。
4. 自社タグを1つ決め、表記を固定する(全角/半角、大文字小文字)。
5. 1〜2か月ごとに効果を見直す。

## 書き方

- **日本語タグは単語を区切る**: スペース、句読点、記号が入るとタグが途切れる(⚪ 一般的な挙動。要確認)。
- 文頭や文中に混ぜるより、**文末にまとめる**方が読みやすい。
- 複数語は `#CamelCase` や `#ひらがな` など可読性を意識。
- 無関係な人気タグを付けるのは**スパム扱いのリスク**があり避ける。
- 数は多ければ良いわけではない。サービスの公式推奨がある場合は従う。

## 管理

[templates/post-plan.md](../../templates/post-plan.md) の「ハッシュタグ」欄に採用タグを記録し、週次で効果を比較する。
