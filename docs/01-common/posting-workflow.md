# 投稿ワークフロー

> **このページで分かること**: 1本の投稿を「企画 → 制作 → 確認 → 投稿 → 反応対応 → 分析 → 改善」の順に進める手順と、各工程でやること・使う道具。
>
> **対象**: 初心者  **先に読むページ**: [はじめての SNS 運用](../00-meta/beginners-guide.md)、[最初の30日](first-30-days.md)

## 概要

SNS 運用が続かない理由の多くは、「毎回ゼロから考える」「投稿して終わり」になることです。決まった流れ(ワークフロー)を作っておくと、**迷う時間が減り、失敗(誤字・権利・広告表記の漏れ)が減り、振り返りで上達できる**ようになります。

このページの流れは一般的な型です(⚪)。自分の生活リズムに合わせて、工程をまとめたり分けたりしてください。

## 用語

| 用語 | 意味 |
|---|---|
| workflow(ワークフロー) | 作業の決まった流れ |
| 予約投稿 | 日時を指定して自動で公開する機能 |
| batching(まとめ作業) | 同じ種類の作業(撮影・文章)をまとめて行うこと |
| repurposing(再利用) | 1つの題材を別の形式・サービスに展開すること |
| KPI(重要業績評価指標) | 成果を測る指標([analytics-kpi](analytics-kpi.md)) |

## 全体像

```
企画 → 制作 → 確認 → 投稿(予約) → 反応対応 → 分析 → 改善
```

## 各工程

| 工程 | やること | 成果物 |
|---|---|---|
| 企画 | 目的・読者・1投稿1メッセージを決める。[投稿計画](../../templates/post-plan.md) | 計画シート |
| 制作 | 文章、画像、動画。画像は [仕様比較](image-specs-comparison.md) に従う | 原稿・素材 |
| 確認 | [画像チェックリスト](../../templates/image-checklist.md)、誤字、リンク、権利、広告表記 | チェック済み |
| 投稿 | 投稿時間を決める。予約機能の有無はサービスごと | 公開 |
| 反応対応 | 最初の数時間はコメントに返信 | 返信 |
| 分析 | 1週間後に指標を確認 [analytics-kpi](analytics-kpi.md) | レビュー |
| 改善 | 次の企画へ反映 | 学び |

## 工程ごとの詳しい手順

### 1. 企画(10〜20分)

1. **目的**を1つ選ぶ: 知ってもらう / 保存してもらう / リンク先に来てもらう / 会話する。
2. **読者**を1人思い浮かべる(例: 「平日の夜に献立を考える会社員」)。
3. **1投稿1メッセージ**: 伝えたいことを1文で書く。2つ以上あれば投稿を分ける。
4. 形式を決める(画像1枚、カルーセル、短尺動画、テキスト)。
5. 計画シート([post-plan](../../templates/post-plan.md))に書く。

### 2. 制作

1. 文章を先に書く([writing-guide](writing-guide.md))。
2. 画像・動画を作る([image-production-workflow](image-production-workflow.md)、[video-basics](video-basics.md))。
3. 書き出し設定は [export-presets](export-presets.md)。
4. 代替テキストを書く([alt-text](alt-text.md))。

### 3. 確認(公開前の5分チェック)

1. 誤字脱字・固有名詞の表記。
2. リンクが正しい行き先に飛ぶか(UTM 付き: [link-in-bio-and-utm](link-in-bio-and-utm.md))。
3. 画像・音楽の権利([image-sources-and-copyright](image-sources-and-copyright.md)、[music-and-licensing](music-and-licensing.md))。
4. 広告・PR の表記([legal-compliance](legal-compliance.md))。
5. 個人情報・位置情報の写り込み([privacy-and-personal-info](privacy-and-personal-info.md))。
6. スマホで実際の見え方([mobile-viewing-optimization](mobile-viewing-optimization.md))。

### 4. 投稿(予約)

1. 投稿時間を決める。最初は**自分が反応に対応できる時間**を優先する(⚪)。
2. 予約投稿は各サービスの公式機能を使う。外部ツールは [tools](tools.md)。
3. 公開直後に、表示崩れ・リンクを自分で確認する。

### 5. 反応対応

1. 公開後しばらくはコメントを確認し、返信する([comments-and-engagement](comments-and-engagement.md))。
2. 誤りの指摘は確認し、必要なら訂正([sensitive-topics-and-accuracy](sensitive-topics-and-accuracy.md))。
3. 荒れたら [crisis-response](crisis-response.md)。

### 6. 分析・7. 改善

1. 1週間後に、表示回数・保存・クリックなど**目的に合った指標**を記録([weekly-review](../../templates/weekly-review.md))。
2. 良かった点・悪かった点を1行ずつ書く。
3. 次の企画で**1つだけ**変えて試す(複数変えると原因が分からない)。

## 投稿頻度の決め方

- 最初は「無理なく続く最小頻度」(例: 週3回)で始め、2〜4週間ごとに見直す。
- 毎日投稿より、**継続できる頻度**を優先する。

## 1週間の進め方の例(⚪)

| 曜日 | 作業 | 目安時間 |
|---|---|---|
| 月 | 先週の振り返り、今週の企画3本 | 30分 |
| 火 | 文章をまとめて書く | 45分 |
| 水 | 画像・動画をまとめて作る | 60分 |
| 木 | 確認と予約投稿の設定 | 20分 |
| 金〜日 | 反応対応(1日10分) | 30分 |

## 再利用(repurposing)

1つの題材を、X(短文・スレッド)→Instagram(画像まとめ)→note(詳細記事)へ展開する。各サービスの形式に合わせ、同一文面のコピペは避ける。

| 元の素材 | 展開先の例 |
|---|---|
| note の詳細記事 | X のスレッド(要点3つ)、Instagram のカルーセル(図解)、メールマガジン |
| 長尺動画 | ショート動画(切り抜き)、ポッドキャスト(音声のみ)([podcast-and-audio](podcast-and-audio.md)) |
| ライブ配信 | アーカイブ、要点のまとめ投稿([live-streaming](live-streaming.md)) |

## よくある失敗と対処

| 失敗 | 対処 |
|---|---|
| 毎日投稿を目標にして2週間で止まった | 週2〜3回から始め、続いたら増やす |
| 投稿してから誤字やリンク切れに気付く | 公開前の5分チェックを必ず通す |
| 数字を見ても何を直せばよいか分からない | 目的に合う指標を1つ決め、1回に1つだけ変える |
| 制作に時間がかかりすぎる | テンプレートを作り、まとめ作業にする |
| 全 SNS に同じ文面を貼る | 形式・文字数・文化に合わせて書き分ける |

## チェックリスト

- [ ] 目的と読者を1文で書いた
- [ ] 公開前の5分チェック(誤字・リンク・権利・広告表記・個人情報・スマホ表示)を通した
- [ ] 投稿後に反応を確認する時間を確保した
- [ ] 1週間後に振り返りを記録した
