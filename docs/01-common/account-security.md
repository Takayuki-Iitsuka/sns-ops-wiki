# アカウント保護

> **このページで分かること**: SNS アカウントを乗っ取り・詐欺から守るために、最初にやる設定と、日々の注意点、万一のときの手順。
>
> **対象**: 初心者(アカウントを作ったばかりの人)/ 複数人で運用する人  **先に読むページ**: なし(最初に読んでください)

## 概要

SNS アカウントは、フォロワーとの関係・投稿の履歴・収益の受け取り先がまとまった「資産」です。乗っ取られると、なりすまし投稿で信用を失ったり、収益の振込先を変えられたり、アカウントを取り戻せなくなったりします。

守り方の基本は次の3つです。

1. **鍵を強くする**: 長く、サービスごとに違うパスワード + 2段階認証。
2. **入口を減らす**: 使わない連携アプリ・ログイン端末を整理する。
3. **だまされない**: 偽の通知・偽のログイン画面に情報を入れない。

> どのサービスでも考え方は共通です。設定画面の名前や場所はサービス・アプリの版で変わるため、本文の UI 名称は ⚪(表記は変わる可能性)です。

## 用語

| 用語 | 意味 |
|---|---|
| two-factor authentication / 2FA(2段階認証、二要素認証) | パスワードに加えて、スマホのアプリや鍵など「もう1つの確認」を求める仕組み |
| multi-factor authentication / MFA(多要素認証) | 2つ以上の要素で本人確認すること。2段階認証とほぼ同じ意味で使われる |
| authenticator app(認証アプリ) | 30秒ごとに変わる確認コードを表示するアプリ(例: Google 認証システム) |
| passkey(パスキー) | 指紋・顔認証・画面ロックでログインする仕組み。パスワードを入力しないため、偽サイトに盗まれにくい |
| security key(セキュリティキー) | USB や NFC で接続する小さな鍵の機器 |
| backup code(バックアップコード) | スマホをなくしたときに使う予備のコード |
| password manager(パスワード管理ツール) | 長いパスワードを生成・保存し、自動入力してくれるツール |
| phishing(フィッシング) | 本物そっくりの偽メール・偽サイトでパスワードなどを盗む詐欺 |
| session(セッション、ログイン状態) | 端末がログインしたままになっている状態 |

## 手順: 最初にやる6つの設定

| # | やること | 理由 | 確度 |
|---|---|---|---|
| 1 | **長く、サービスごとに違うパスワード**にする | 1つ漏れても他は守れる | 🟡 総務省は「10文字以上」「サービスごとに異なる」パスワードを推奨(検索要約経由) |
| 2 | **2段階認証を有効化** | パスワードが漏れても入られにくい | ⚪ |
| 3 | **バックアップコードを保管** | スマホ紛失時の締め出しを防ぐ | ⚪ |
| 4 | **登録メールアドレスを守る**(メールにも2段階認証) | メールが乗っ取られると、パスワード再設定で全アカウントが危険 | ⚪ |
| 5 | **連携アプリを棚卸し** | 古い連携が乗っ取りの入口になる | ⚪ |
| 6 | **ログイン通知を有効化** | 知らないログインにすぐ気づける | ⚪ |

### 1. パスワードを作る

1. パスワード管理ツールを用意する(スマホやブラウザに付属の機能でもよい)。
2. ツールの生成機能で、**長くランダムな**パスワードを作る。総務省の「国民のためのサイバーセキュリティサイト」は、10文字以上で、数字・記号・大文字・小文字を混ぜることを推奨しています(🟡 検索要約。本文は未取得)。
3. **サービスごとに別のパスワード**にする。使い回しは厳禁です。
4. 同サイトは、**流出などの事実がなければ定期的な変更は不要**としています(🟡 同上)。変更が必要なのは、漏えいの通知を受けたとき・心当たりのないログインがあったときです。

### 2. 2段階認証を設定する

確認方法には強さの差があります(⚪ 一般的な整理)。

| 方法 | 強さ | 注意 |
|---|---|---|
| パスキー / セキュリティキー | 高い | 偽サイトにだまされにくい。予備の鍵も登録する |
| 認証アプリ | 中〜高 | スマホの機種変更時に引き継ぎが必要 |
| SMS(ショートメッセージ)のコード | 低め | 電話番号の乗っ取り(SIM スワップ)に弱い。**他に方法がないときの最終手段** |

- 例として Google アカウントでは、パスキー、ハードウェア セキュリティ キー、Google からのメッセージ、確認コードアプリ、SMS・音声通話のコード、バックアップ コード(8桁)などが使えます(✅ Google アカウント ヘルプ)。
- 各 SNS の設定場所は、サービス別ページの「アカウント設定」を参照してください(例: [X](../02-x/01-account-setup.md)、[Instagram](../03-instagram/01-account-setup.md))。

### 3. バックアップコードを保管する

- 紙に印刷して自宅の安全な場所に置く、またはパスワード管理ツールの「メモ」に保存する。
- **このリポジトリ・クラウドの共有フォルダ・SNS の下書き・スクリーンショットには置かない**(このリポジトリは public です)。

### 4〜6. 定期点検(月1回、5分)

1. 設定の「ログイン中の端末(セッション)」を開き、知らない端末をログアウトさせる。
2. 「連携アプリ」「アプリとウェブサイト」を開き、使っていない連携を解除する。
3. 登録メールアドレス・電話番号が最新か確認する。
4. ログイン通知がオンになっているか確認する。

## 具体例: 詐欺・乗っ取りの手口

| 手口 | 典型的な文面 | 正しい対応 |
|---|---|---|
| 偽の警告 DM・メール | 「著作権侵害の報告がありました。24時間以内に異議申立てしないと停止します」 | リンクを開かない。**公式アプリの通知欄**で確認する |
| 偽の認証バッジ申請 | 「認証マークを付与します。こちらから申請を」 | 公式は DM で申請を勧誘しない前提で疑う(⚪) |
| 案件・コラボ依頼を装う | 「PR の資料です」と ZIP や実行ファイルを送る | 知らない相手のファイルは開かない。資料は本文で送ってもらう |
| ログインコードの聞き出し | 「間違えてあなたの番号にコードを送りました。教えてください」 | **確認コードは誰にも教えない** |
| 偽のログイン画面 | 本物そっくりのページでパスワード入力を求める | URL を確認。パスワード管理ツールが自動入力しないページは偽物を疑う |

- 公式を名乗るアカウントでも、**認証済み表示だけで信用しない**。

## 複数人で運用する場合

- 共有アカウントのパスワードを口頭やチャットで共有するのは避け、サービスの**権限機能**(メンバー招待、ビジネス用の管理画面など)を使う。
- 権限は「投稿だけ」「分析だけ」など**必要最小限**にする。
- 退任者の権限は**即日削除**し、共有していた情報があれば変更する。
- 誰がいつ何の権限を持っているかを、非公開の台帳に記録する。

## よくある失敗と対処

| 失敗 | 起きること | 対処 |
|---|---|---|
| 機種変更で認証アプリを引き継がなかった | ログインできなくなる | 機種変更の**前に**引き継ぎ。バックアップコードを手元に |
| SNS とメールで同じパスワード | 1つ漏れると全部入られる | パスワード管理ツールで全部別にする |
| 登録メールが昔のフリーメールのまま | 再設定メールを受け取れない | 普段使うメールに変更し、2段階認証を付ける |
| 「便利そう」で連携したアプリを放置 | 勝手に投稿・DM される | 月1回の棚卸し |
| バックアップコードをスクショで保存 | 写真のクラウド同期で漏れる | 印刷するか、管理ツールに保存 |

## 万一のとき(乗っ取られた・疑わしいとき)

1. **まだログインできる**なら: パスワード変更 → 全端末からログアウト → 連携アプリを全解除 → 2段階認証を再設定。
2. **ログインできない**なら: 各サービスの**公式の乗っ取り申告フォーム**から復旧を申請する(サービス別ページの「ポリシー」節を参照)。
3. 他サービスで同じパスワードを使っていれば**すべて変更**。
4. 登録メールが乗っ取られていないか確認し、メールのパスワードも変更。
5. フォロワーに向けて、別のアカウントや別サービスから「乗っ取られたので DM のリンクを開かないで」と告知する([crisis-response](crisis-response.md))。
6. 何が起きたかを時系列でメモし、スクリーンショットを非公開で保存する。

## 注意点

- 2段階認証の方式・設定場所・復旧方法は**サービスごとに違い、変更も多い**です。設定前に各サービスのヘルプを確認してください(⚪)。
- 確認コード・バックアップコード・パスワードを、このリポジトリやチャットの公開チャンネルに書かない(→ [CONTRIBUTING](../../CONTRIBUTING.md))。
- API の鍵(トークン)の管理は [20-api/01-concepts-and-security](../20-api/01-concepts-and-security.md)。
