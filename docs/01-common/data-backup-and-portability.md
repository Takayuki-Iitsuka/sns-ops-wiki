# アカウントデータのバックアップと持ち出し

> **このページで分かること**: 投稿・読者・成果のデータを自分の手元に残す方法(公式の書き出し機能、保存のルール)と、凍結・サービス終了・引っ越しへの備え。
>
> **対象**: 初心者〜中級者  **先に読むページ**: [account-security](account-security.md)

アカウント凍結・サービス終了・仕様変更に備え、**投稿・読者・成果を自分の手元に残す**方法です。公式の書き出し機能の名称・手順は変わるため、各サービスの設定画面で確認してください(#60)。

## 概要

SNS に投稿したデータは、サービスの中にあります。もしアカウントが凍結されたり、乗っ取られたり、サービスが終了したりすると、何年分もの投稿や読者とのつながりを一度に失うことがあります。

備えは2つです。

1. **バックアップ**: 投稿の元データと記録を、自分の管理する場所に保存する。
2. **持ち出し(ポータビリティ)**: サービスの公式の書き出し機能でデータを受け取り、別の場所でも読者に届く手段を持つ。

## 用語

| 用語 | 意味 |
|---|---|
| backup(バックアップ) | 元に戻せるように、データの複製を別の場所に保存すること |
| data export / data download(データの書き出し、ダウンロード) | サービスが用意する、自分のデータを一括で受け取る機能 |
| archive(アーカイブ) | 書き出したデータをまとめたファイル(多くは ZIP 形式) |
| data portability(データポータビリティ) | 自分のデータを別のサービスへ持ち運べること |
| ZIP / JSON / HTML | まとめたファイルの形式 / プログラムで扱いやすい形式 / ブラウザで見られる形式 |
| encryption(暗号化) | パスワードがないと中身を読めないようにすること |
| account suspension(凍結、アカウント停止) | 規約違反などでアカウントが使えなくなること |
| appeal(異議申立て) | 凍結や削除の判断に対して見直しを求めること |

## 1. 何を守るか

| 対象 | 重要度 | 例 |
|---|---|---|
| 投稿の元データ(画像・動画・文章・alt) | 高 | マスター画像、台本、記事の原稿 |
| 投稿の履歴・成果 | 中 | インサイトの数値、日付 |
| 読者への連絡先 | 高 | メール、LINE 公式の友だち(自前の資産) |
| 収益・取引の記録 | 高 | 売上、請求、支払調書 |
| アカウントの設定 | 中 | プロフィール文、リンク、ハイライト |

## 2. サービス別の書き出し

| サービス | 公式の書き出し機能(名称は変わる可能性) | 確度 |
|---|---|---|
| X | 設定の「データのアーカイブをダウンロード」(請求後に準備される)。設定 → アカウント → 「あなたの X データ」で本人確認コードを入力 → 依頼。準備ができるとメール・通知が届き、ZIP をダウンロード | 🟡 help.x.com(検索要約) |
| Instagram / Facebook / Threads | アカウントセンターの「あなたの情報とアクセス許可」→「情報のダウンロード」。形式は HTML か JSON、期間・画質を選べる | 🟡 解説記事 |
| YouTube / Google | **Google Takeout**(動画・コメント・チャンネル情報)。形式は **.zip / .tgz**、準備は「数分から数日」、リンクは**約7日で期限切れ**、各アーカイブのダウンロードは**5回まで**。**2か月ごと・1年間**の定期エクスポートも可 | ✅ Google アカウント ヘルプ |
| TikTok | 設定のデータのダウンロード | ⚪ |
| note | 記事のエクスポート機能の有無は未確認(**原稿は自分の手元に**) | ⚪ |
| Bluesky | リポジトリの書き出し(AT Protocol。アカウントが自分のサーバー間で移行可) | ⚪ |
| LINE 公式 | 友だちリストの書き出しは制限あり(要確認) | ⚪ |

### 書き出しの手順(共通の流れ)

1. パソコンのブラウザで、そのサービスに**ログイン**する(スマホより大きなファイルを扱いやすい)。
2. 設定から「データのダウンロード」「情報のダウンロード」などの項目を探す。
3. 本人確認(パスワード・確認コード)を行う。
4. 対象(全部 / 一部)、期間、形式を選んで依頼する。迷ったら**全部・閲覧用(HTML)**。プログラムで使うなら JSON も。
5. 準備完了の通知を待つ(すぐ〜数日)。
6. 期限内にダウンロードし、**開いて中身を確認**する。
7. 暗号化した保存先に移し、ダウンロードフォルダからは削除する。

## 3. 運用ルール

1. **元データは先に自分のストレージへ**(投稿してから取り出すのではなく、制作時に保存)。
2. **月1回**、公式の書き出しを実行し、非公開の場所に保管。
3. 書き出したファイルには**個人情報**が含まれる。**暗号化**したストレージに、このリポジトリ(public)には置かない。
4. **3-2-1 ルール**(⚪): データを3つ、媒体を2種類、1つは別の場所に。
5. **復元できるか**を年1回確認(開いてみる)。
6. **分析の数字は早めに記録**: X の API では、非公開・オーガニック指標は**作成から30日以内の投稿のみ**取得できます(✅)。週次で記録しておきます([analytics-kpi](analytics-kpi.md))。

### 3-2-1 ルールの例(⚪)

| 何を | どこに |
|---|---|
| 1つ目(作業用) | パソコン本体 |
| 2つ目(別の媒体) | 外付けの SSD / HDD |
| 3つ目(別の場所) | クラウドストレージ(2段階認証+暗号化) |

## 4. 凍結・停止の備え

| 項目 | 内容 |
|---|---|
| **別拠点** | note・メール・LINE・Bluesky・自サイトなど、**読者に直接届く場所**を持つ |
| 連絡先の収集 | メルマガ、LINE 友だち、メンバーシップ(自前)([newsletter-and-email](newsletter-and-email.md)) |
| プロフィールの予備 | 別のサービスにも同じ名前・リンクを確保(なりすまし対策) |
| 異議申立ての記録 | 違反通知の内容、投稿の保存、時系列 |
| 連絡窓口 | 各サービスの異議申立て・サポート([10-policies](../02-x/10-policies.md) など) |
| 乗っ取り時 | [account-security](account-security.md) |

## 5. 移行(別サービスへの引っ越し)

1. 読者に**事前に告知**(プロフィール・固定投稿)。
2. 新拠点のリンクを**全サービスのプロフィール**に。
3. 旧アカウントは**削除せず**、案内を残して凍結を避ける(一定期間)。
4. 画像・記事の権利を確認して再投稿。

## 6. API で取得する場合

読み取り専用のトークンで、自分のデータを定期取得(X は Owned Reads $0.001/件 ✅)。[20-api/10-benefits-of-api](../20-api/10-benefits-of-api.md)

## よくある失敗と対処

| 失敗 | 起きること | 対処 |
|---|---|---|
| 書き出しを依頼したまま期限切れ | ダウンロードできない(Google は約7日 ✅) | 通知が来たらその日に保存 |
| 元画像を SNS にしか残していない | 凍結で作品を失う | 制作時にマスターを保存 |
| 書き出しファイルを共有フォルダに置いた | DM や連絡先が漏れる | 暗号化した非公開の場所へ |
| 保存したが一度も開いていない | 壊れていても気づかない | 年1回、復元できるか確認 |
| 読者との接点が1つの SNS だけ | 凍結で全員とつながりが切れる | メール・別サービスなどの別拠点を持つ |

## 注意点

- 書き出し機能の名前・場所・形式は頻繁に変わります(⚪ #60)。
- 書き出したデータには、自分だけでなく**相手の DM・コメント**も含まれることがあります。取り扱いに注意します([privacy-and-personal-info](privacy-and-personal-info.md))。

## チェックリスト

- [ ] 元データ(画像・動画・原稿)を制作時に自分のストレージへ保存している
- [ ] 主要サービスの書き出しを月1回実行している
- [ ] 保存先は3-2-1 ルールで、暗号化されている
- [ ] 読者に直接届く別拠点がある
- [ ] 年1回、バックアップを開いて確認した
