# アカウントデータのバックアップと持ち出し

アカウント凍結・サービス終了・仕様変更に備え、**投稿・読者・成果を自分の手元に残す**方法です。公式の書き出し機能の名称・手順は変わるため、各サービスの設定画面で確認してください(#60)。

## 1. 何を守るか

| 対象 | 重要度 | 例 |
|---|---|---|
| 投稿の元データ(画像・動画・文章・alt) | 高 | マスター画像、台本、記事の原稿 |
| 投稿の履歴・成果 | 中 | インサイトの数値、日付 |
| 読者への連絡先 | 高 | メール、LINE 公式の友だち(自前の資産) |
| 収益・取引の記録 | 高 | 売上、請求、支払調書 |
| アカウントの設定 | 中 | プロフィール文、リンク、ハイライト |

## 2. サービス別の書き出し(⚪ 要確認)

| サービス | 公式の書き出し機能(名称は変わる可能性) |
|---|---|
| X | 設定の「データのアーカイブをダウンロード」(請求後に準備される) |
| Instagram / Facebook / Threads | アカウントセンターの「あなたの情報とアクセス許可」→「情報のダウンロード」 |
| YouTube / Google | **Google Takeout**(動画・コメント・チャンネル情報) |
| TikTok | 設定のデータのダウンロード |
| note | 記事のエクスポート機能の有無は未確認(**原稿は自分の手元に**) |
| Bluesky | リポジトリの書き出し(AT Protocol。アカウントが自分のサーバー間で移行可) |
| LINE 公式 | 友だちリストの書き出しは制限あり(要確認) |

## 3. 運用ルール

1. **元データは先に自分のストレージへ**(投稿してから取り出すのではなく、制作時に保存)。
2. **月1回**、公式の書き出しを実行し、非公開の場所に保管。
3. 書き出したファイルには**個人情報**が含まれる。**暗号化**したストレージに、このリポジトリ(public)には置かない。
4. **3-2-1 ルール**(⚪): データを3つ、媒体を2種類、1つは別の場所に。
5. **復元できるか**を年1回確認(開いてみる)。

## 4. 凍結・停止の備え

| 項目 | 内容 |
|---|---|
| **別拠点** | note・メール・LINE・Bluesky・自サイトなど、**読者に直接届く場所**を持つ |
| 連絡先の収集 | メルマガ、LINE 友だち、メンバーシップ(自前) |
| プロフィールの予備 | 別のサービスにも同じ名前・リンクを確保(なりすまし対策) |
| 異議申立ての記録 | 違反通知の内容、投稿の保存、時系列 |
| 連絡窓口 | 各サービスの異議申立て・サポート([10-policies](../02-x/10-policies.md) など) |
| 乗っ取り時 | [account-security](account-security.md) |

## 5. 移行(別サービスへの引っ越し)

1. 読者に**事前に告知**(プロフィール・固定投稿)。
2. 新拠点のリンクを**全サービスのプロフィール**に。
3. 旧アカウントは**削除せず**、案内を残して凍結を避ける(一定期間)。
4. 画像・記事の権利を確認して再投稿。
