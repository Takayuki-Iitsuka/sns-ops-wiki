# 画像の説明文(alt text、代替テキスト)詳細ガイド

**alt text(代替テキスト)**は、画像の内容を文字で説明するテキストです。スクリーンリーダー(画面読み上げ)で聞く人、画像が読み込めない人、検索や AI が画像を解釈する場面で使われます。

> ✅ は公式文書(X API、Instagram API)で確認した項目、🟡/⚪ は二次資料・一般知識です。各サービスの**アプリ画面での手順・上限**は公式ヘルプ未取得のため ⚪ が残っています(#8, #16)。

## 1. なぜ書くか

| 理由 | 内容 |
|---|---|
| **アクセシビリティ** | 視覚障害・低視力の人が、iPhone の **VoiceOver**、Android の **TalkBack** で画像の内容を知る |
| 状況による利用 | 運転中・通信が遅く画像が読み込めない・画面を見られない場面 |
| 検索・解析 | 検索エンジンや AI が画像の内容を理解する手がかり(効果の大きさは未検証 ⚪) |
| 法的背景(日本) | 障害者差別解消法の改正により、事業者による**合理的配慮が義務**となった(2024年(皇紀2684年・令和6年)4月1日施行と一般に説明される ⚪ 要確認)。ウェブのアクセシビリティの基準は **WCAG(1.1.1 非テキストコンテンツ)**、日本の **JIS X 8341-3** |
| 信頼 | 丁寧な運用の表れ。ブランド・個人の信頼につながる |

## 3. 書き方の原則

1. **見えているものを事実で書く**: 誰が・何を・どこで・どうしている。
2. **文脈で変える**: 同じ写真でも、記事の目的(商品紹介か、旅行記か)で書くべき情報が違う。
3. **画像内の文字は全文書く**(スクリーンショット、チラシ、バナー、図表)。ただし本文に同じ文があれば要約可。
4. **「画像」「写真」で始めない**(読み上げで画像と分かる)。図表・イラスト・スクリーンショットなど**種別だけ**は有用。
5. **宣伝文句・キーワードの詰め込み禁止**。説明に徹する。
6. **主観の押し付けを避ける**(「美しい」「かわいい」は避け、見える特徴を書く。感情が主題の場合は短く)。
7. **本文と alt の二重化を避ける**: 同じ文章を本文と alt に書くと、読み上げが重複する。alt は画像固有の情報。
8. **長さの目安**: **多くは 80〜150字**。複雑な図は短い alt + 本文に詳細。上限(1,000字)まで使わない。
9. **個人を特定しない**: 実在の人物の名前は、本人の許可や公開の文脈がある場合のみ。顔つきや属性の推測を書かない。
10. **更新**: 画像を差し替えたら alt も更新。

## 4. 画像の種類別の書き方

| 種類 | 書くこと | 例 |
|---|---|---|
| **写真(風景・物)** | 被写体・場所・特徴・雰囲気(必要なら) | 「雪をかぶった富士山を、手前の桜越しに撮影した写真。空は晴れている」 |
| **人物** | 人数・動作・服装など目的に関わる特徴。本人確認できない場合は名前を書かない | 「作業机でノートパソコンに向かい、手元のメモを見ながら入力する人」 |
| **商品** | 商品名・色・形・サイズ感・付属品 | 「白い陶器のマグカップ。持ち手は黒。ロゴは側面に小さく入っている」 |
| **スクリーンショット** | どの画面か・主要な表示・強調箇所・文字 | 「Instagram のインサイト画面。リーチの折れ線グラフは右上がり。保存数は先週より増加と表示」 |
| **グラフ** | 種類・軸・傾向・最大/最小・結論 | 「折れ線グラフ。10月のフォロワー数が1週目の120人から4週目の310人に増加」 |
| **表** | 何の表か・列/行・要点。大きな表は本文へ | 「料金比較の表。Pro は2,900円、Plus は1,200円」 |
| **インフォグラフィック** | 主題・構成・各項目の要点。長ければ本文へ | 「SNS 運用の週次サイクルを4ステップで示した図。企画、制作、投稿、振り返りの順」 |
| **フロー図・関係図** | 起点→終点・分岐・矢印の意味 | 「X の投稿が note の記事へ誘導され、そこから購入ページへ進む流れ図」 |
| **文字入り画像(バナー・告知)** | 文字の全文+デザイン上の補足 | 「告知バナー。『11月10日 公開』と大きく書かれ、背景は青」 |
| **漫画・4コマ** | コマごとの出来事とセリフ(長ければ本文へ) | 「4コマ。1コマ目、…。2コマ目、…」 |
| **イラスト** | 描かれている主題・様式 | 「手描き風のイラスト。猫が机の上のノートパソコンの隣で眠っている」 |
| **AI 生成画像** | 「AI 生成」と明記+内容 | 「AI で生成した、夕焼けの海岸のイラスト」 |
| **ロゴ・アイコン** | 名称と意味 | 「sns-ops-wiki のロゴ。青い円の中に白い吹き出し」 |
| **地図** | 場所・範囲・目印 | 「渋谷駅周辺の地図。駅の北側にハチ公像の位置が丸で示されている」 |
| **ミーム・画像ジョーク** | 画像と文字の両方・意図が分かるように | 「猫が驚く顔の画像に『締め切り前日の私』と書かれている」 |
| **装飾(区切り線、背景)** | SNS では空にできないことが多い。**短く**「区切り線」など | 「装飾の区切り線」 |
| **動画のサムネイル** | 動画の主題 | 「動画の表紙。『X API の移行』の文字と、青い背景」 |

## 5. 日本語特有の注意

| 論点 | 対策 |
|---|---|
| 固有名詞の読み | 難読語は alt では漢字+必要ならひらがな(読み上げエンジンが誤読する場合) |
| 絵文字 | スクリーンリーダーは**絵文字の名前を読み上げる**ので、多用しない・飾りに使わない |
| 記号・顔文字 | 読み上げで意味不明になる。使わない |
| 英数字 | 半角で。全角は読み方が変わる場合がある(⚪) |
| ハッシュタグ | 複数語は **CamelCase / PascalCase**(例: `#SnsOps`)にすると語の切れ目が伝わる(⚪)。日本語は漢字・カタカナで区切りが伝わりやすい |
| 数字の単位 | 「120人」「4週目」と単位を書く |
| 長い一文 | 句点で区切る(読み上げの息継ぎ) |

## 6. カルーセル(複数枚)の書き方

- **各画像に固有の alt**を付ける(同じ文の使い回しは避ける)。
- 1枚目の alt に全体の主題、2枚目以降は「続き」と分かるように要点。
- 内容が文字中心なら、**本文に全文**を書き、alt は画像の見た目と構成(図解など)に絞る。
- Instagram の API では、alt は**カルーセル内の画像**にも付けられる(動画は対象外)✅。

## 7. 悪い例と良い例

| 悪い例 | 理由 | 良い例 |
|---|---|---|
| `写真` | 情報がない | 「机の上のノートパソコンと、週次計画を書いた付箋3枚」 |
| `画像: グラフ` | 種別のみ | 「折れ線グラフ。10月のフォロワー数が120人から310人に増加」 |
| `#SNS運用 #フォロワー増やす 画像` | キーワードの羅列 | 説明に徹する |
| `美しい夕日` | 主観のみ | 「海に沈む夕日。空は赤からオレンジ、手前に岩場」 |
| `おしゃれなカフェの店内` | 主観 | 「木のテーブルが並ぶカフェの店内。窓際に観葉植物」 |
| 本文と同じ文章を貼る | 読み上げが二重 | 画像固有の情報(見た目・構成)に絞る |

## 8. テンプレート

```
[種類]。[主題]が[場所/状況]で[状態/動作]。(画像内の文字:「…」)(補足:色/配置)
```

- スクリーンショット: `[サービス名]の[画面名]。[主要な表示]。[強調された箇所]。`
- グラフ: `[種類]のグラフ。縦軸は[…]、横軸は[…]。[傾向]。[最大/最小]。`
- バナー: `[用途]のバナー。「[文字]」と書かれ、背景は[色]。`

## 9. 動画・音声のアクセシビリティ

| 項目 | 対策 |
|---|---|
| **字幕(キャプション)** | 発言と重要な効果音を文字に。自動字幕は**必ず確認・修正**。字幕ファイル(SRT)を用意できるサービスでは別ファイル(YouTube など) |
| **文字起こし(トランスクリプト)** | 説明文・記事に全文または要約を載せる |
| **音声解説** | 映像だけで伝わる情報(画面操作など)を、ナレーションで言葉にする |
| **色** | 色だけで区別しない(記号や形を併用)。コントラスト比 4.5:1 以上 |
| **点滅** | 1秒に3回を超える点滅を避ける(光過敏性発作への配慮。WCAG の基準 ⚪) |
| **音量・BGM** | 声が聞き取れる音量バランス |
| **動画の要点** | 本文(キャプション)にも書く |

## 10. AI で alt を作るとき

- 生成 AI や各サービスの**自動 alt**は誤りがある(ハルシネーション)。**必ず確認**し、事実と一致させる。
- **人物の特定・属性(年齢・国籍・病気など)の推測は書かせない**。
- 画像内の文字は**自分で照合**。
- プロンプト例: 「次の画像を、視覚に障害のある読者向けに、事実だけで100字程度、主観を避けて日本語で説明して。画像内の文字は全文書いて。人物の名前や属性は推測しないで。」
- AI の出力を使う場合も、[ai-usage-policy](ai-usage-policy.md) に従う。

## 11. 運用

### ワークフロー

1. **画像を作る時に alt を同時に書く**(後回しにしない)。
2. [alt-text-log](../../templates/alt-text-log.md) に記録(画像ファイル名・alt・本文との分担)。
3. 投稿時に各サービスの alt 欄に入力。
4. 公開後、**VoiceOver / TalkBack** で読み上げを確認(下記)。
5. 週次で 5 件サンプルをレビュー。

### 読み上げのテスト手順

- **iPhone**: 設定 → アクセシビリティ → VoiceOver をオン。投稿をフリックして読み上げを確認(⚪)。
- **Android**: 設定 → ユーザー補助 → TalkBack をオン(⚪)。
- 読み上げで**意味が通るか・長すぎないか・二重になっていないか**を見る。

### KPI

| 指標 | 目標 |
|---|---|
| alt 付与率(画像投稿のうち alt があるもの) | **100%** |
| 平均文字数 | 80〜150字 |
| 動画の字幕付与率 | 100% |

## 12. 注意

- alt は**画像の説明**であり、広告ではない。広告・PR の表記は本文に([legal-compliance](legal-compliance.md))。
- 画像に含まれる他人の個人情報(顔・ナンバー・住所)は alt に書かない。
- センシティブな画像は、事実のみを短く。
