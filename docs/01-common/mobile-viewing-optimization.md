# スマートフォンで最も見やすい画像・動画の考察

> **このページで分かること**: スマホの画面の大きさから逆算した、画像・動画の推奨サイズ・比率・文字の大きさ。結論だけ知りたい場合は §8 へ。
>
> **対象**: 初心者〜中級者  **先に読むページ**: [image-specs-comparison](image-specs-comparison.md)、[video-specs-comparison](video-specs-comparison.md)

## 概要

SNS の閲覧は大半がスマートフォンです。**iPhone と Android の画面特性から、どのサイズ・比率・文字サイズが「世間的に最も見やすい」か**を、計算に基づいて考察します。

> 画面の解像度・論理幅は端末の公開仕様に基づく一般知識(⚪)、利用割合と一般的な論理幅は検索で得た二次資料(🟡)です。**最終判断は自分の実機での確認**(末尾のテスト手順)。

## 用語

| 用語 | 意味 |
|---|---|
| px / pixel(ピクセル、画素) | 画像や画面を構成する点。画像の「1080×1350」は横 1080 点・縦 1350 点 |
| pt / dp(論理ピクセル) | 端末の画面を「標準的な見た目の大きさ」で数える単位。iPhone は pt、Android は dp。物理的な画素数とは異なる |
| 倍率(@2x、@3x) | 1pt を何 px で表示するか。@3x なら 1pt = 3px |
| aspect ratio(アスペクト比、縦横比) | 横:縦 の比。4:5 は縦長、16:9 は横長 |
| safe area(安全領域) | アプリの UI(ボタン・文字)が重ならない中央の領域 |
| sRGB / Display P3 | 色の範囲(色空間)の規格。sRGB が Web の標準、P3 はより広い |
| SDR / HDR | 標準の明るさの映像 / 明暗の幅が広い映像 |
| OLED(有機 EL) | 画素自体が光る画面。黒が深いが暗部の表現に癖がある |

## 1. 前提: 端末の画面

### 日本の利用割合(2026年(皇紀2686年・令和8年)、🟡 StatCounter、モバイル OS)

| 月 | iOS | Android |
|---|---|---|
| 2026年6月 | 約 59% | 約 41% |
| 7月 | 63.6% | 36.4% |
| 8月 | 64.7% | 35.3% |
| 9月 | 60.5% | 39.5% |

→ **おおむね iPhone 6 : Android 4**。月ごとの揺れが大きい(サンプリング差)。ウェブ閲覧の統計で、SNS アプリの利用割合そのものではない。**どちらにも最適化が必要**。

### 代表的な端末の画面(⚪ メーカー公開仕様。要確認)

| 端末(例) | 物理解像度(px) | 論理幅(pt / dp) | 倍率 | 縦横比 |
|---|---|---|---|---|
| iPhone SE(第3世代) | 750×1334 | 375 | @2x | 16:9 |
| iPhone 15 / 16 | 1179×2556 | **393** | @3x | 約 19.5:9 |
| iPhone 16 Pro / 17 | 1206×2622 | 402 | @3x | 約 19.5:9 |
| iPhone 15 Plus / 16 Plus | 1290×2796 | 430 | @3x | 約 19.5:9 |
| iPhone 16 Pro Max | 1320×2868 | 440 | @3x | 約 19.5:9 |
| Pixel 9 | 1080×2424 | 約 **412** | 約 2.6 | 約 20:9 |
| Galaxy S シリーズ(標準設定) | 1080×2340 | **360** | @3x | 約 19.5:9 |
| 高精細設定(QHD+) | 1440×3120 | 360〜412 | — | 約 19.5:9 |

- 検索した二次資料でも、iOS は **390〜393** が主流、Android は **360** と **412** が一般的な論理幅(🟡)。
- **Android の多くは 1080px 幅(FHD+)が標準**。QHD+ は設定で選ぶ高精細モード。
- 画面の縦横比は **約 19.5:9〜20:9(縦に細長い)**。動画の 9:16 (=16:9 の縦) より縦長。

## 2. 考察①: 画像の幅 — 1080px がちょうど良い

| 観点 | 結論 |
|---|---|
| iPhone(393pt、@3x = 1179px) | 1080px 幅の画像は約 **9% 拡大**されて表示される(1179/1080)。目立たない |
| Android(1080px 幅が標準) | 1080px 幅は**等倍**で最もシャープ |
| プラットフォーム側の制限 | Instagram・Threads の API は**幅 320〜1440px**に収める(✅)。アプリのフィードも幅 1080px で処理される(🟡) |
| 1440px 以上を出す意味 | Instagram・Threads では**縮小される**。X・note・YouTube は大きいほど有利な場面があるが、スマホ表示では効果が薄い |

→ **フィード画像は幅 1080px を標準**にする。サムネイルや高精細表示が必要な場合のみ大きく(YouTube のサムネイルは公式で 3840×2160 を推奨 ✅)。

## 3. 考察②: 縦横比 — 4:5(1080×1350)が最も汎用的

| 比率 | 画面に占める高さ(393pt 幅の iPhone) | 投稿先での扱い | 評価 |
|---|---|---|---|
| 1.91:1(横長) | 約 206pt(画面高の約 24%) | Instagram 許容範囲の端 ✅ | 情報量が小さい |
| 1:1 | 393pt(約 46%) | すべて可 | 無難 |
| **4:5** | **約 491pt(約 58%)** | Instagram ✅(4:5〜1.91:1)、Threads ✅、X は 2:1〜3:4 の範囲内で**全体表示**(🟡) | **最も大きく見せられる共通比率** |
| 3:4 | 約 524pt(約 61%) | Instagram は未確認(#4)。X は範囲の端 | 一部で切れる可能性 |
| 9:16(縦動画) | フルスクリーン | リール・ショート・TikTok | 動画の標準 |

→ **静止画の共通マスターは 1080×1350(4:5)**。同じ画像を Instagram・Threads・X・Facebook に出せ、スマホで最も画面を占有できる。必要に応じて 1:1 や 1.91:1 を派生させる。

## 4. 考察③: 文字サイズ — 「画面上の pt」から逆算する

画像を画面幅いっぱいに表示すると、**1画像 px あたりの画面上の大きさ**は次の式で決まる。

```
倍率(pt/px) = 画面の論理幅(pt) ÷ 画像の幅(px)
画像内の文字の高さ(px) = 画面上で必要な高さ(pt) ÷ 倍率
```

### 1080px 幅の画像(Instagram・Threads・X のフィード)

| 画面幅 | 倍率 | 画面で 12pt に必要な px | 14pt に必要な px | 17pt(標準の本文)に必要な px |
|---|---|---|---|---|
| 360(Galaxy 標準) | 0.333 | 36px | **42px** | 51px |
| 375(iPhone SE) | 0.347 | 35px | 40px | 49px |
| 393(iPhone 15/16) | 0.364 | 33px | 38px | 47px |
| 412(Pixel) | 0.381 | 31px | 37px | 45px |

→ **本文は 44px 以上(推奨 48px)、補足・注釈は 36px 以上(最小)、見出しは 72px 以上**を目安に。360dp の端末でも 14pt 相当で読める。

### 他のサイズの画像で必要な文字の大きさ(論理幅 360 を基準、14pt 相当)

| 表示 | 画像の幅 | 倍率(360 基準) | 14pt に必要な px |
|---|---|---|---|
| フィード画像 | 1080 | 0.333 | **42px** |
| note の見出し画像(記事の幅) | 1280 | 約 0.28(360-余白) | 約 **50px** |
| 横動画を縦持ちで視聴(幅いっぱい) | 1920 | 0.1875 | 約 **75px** |
| 横動画を横向きフルスクリーン(高さ 360) | 1080(高さ) | 0.333 | 42px |
| **YouTube の一覧サムネイル(表示幅 約 168pt)** | 1280 | 約 0.13 | 約 **107px**(1280×720 の画像で見出し文字はこれ以上) |
| プロフィールのグリッド(1/3 幅 約 131pt) | 1080 | 約 0.12 | 約 115px(**グリッドでは文字は読めない**。中央に主題だけ) |

- **サムネイルは「小さく表示される」**。1280×720 の画像なら、文字は **100px 以上**、6語以内。
- 横長の 16:9 動画を**縦持ちで見る人は多い**。字幕・図の文字を大きくする。

### 1行の文字数(日本語)

- 1080px 幅、左右余白 各 90px → 本文領域 900px。文字 44px(全角)で **約 20字/行**。
- **1行 18〜20字以内**、行間は文字高の 1.4〜1.6 倍、1枚に 3〜5 行までが読みやすい(⚪)。
- 縦書きは行数を減らし、ルビや小さな注は避ける。

## 5. 考察④: 動画 — 9:16 の 1080×1920、30fps、SDR

| 項目 | 推奨 | 理由 |
|---|---|---|
| 比率・解像度 | **9:16、1080×1920** | 縦持ちフルスクリーンの標準。リール・ショート・TikTok・Threads・X で共通 |
| フレームレート | 撮影と同じ。**30fps を基本**、動きの速い映像は 60fps | YouTube は撮影時と同じで書き出し ✅ |
| 色 | **SDR(Rec.709 / sRGB)を基本** | iPhone は HDR(Dolby Vision など)で撮影・保存できるが、**プラットフォームでの再生・変換が端末により異なる**。ストア品質を揃えるなら SDR(⚪) |
| コーデック | H.264(+AAC)、必要なら HEVC | Instagram・Threads は H.264/HEVC 可 ✅、YouTube は H.264 推奨 ✅ |
| ビットレート | 1080p で **8〜12Mbps**(YouTube 推奨 8Mbps、60fps は 12Mbps ✅) | 画質と通信量の両立 |
| 長さ | 冒頭3秒で主題 | — |
| 安全領域 | 上 約10%、下 約15%、右 約15% を空ける | アプリの UI(アカウント名、キャプション、ボタン)が重なる(⚪) |
| 字幕 | **必ず付ける**。画面中央〜やや上 | 音なし再生が多い(⚪) |

- 端末の縦横比は 19.5:9〜20:9 で、9:16 より**縦に長い**。アプリにより**上下に余白が出る/左右が切り取られる**など挙動が異なる。重要な要素は**中央に**。

## 6. 考察⑤: 色・明るさ・ダークモード

| 項目 | 推奨 |
|---|---|
| 色空間 | **sRGB で書き出し**(Instagram・Threads の API は他の色空間を sRGB に変換 ✅)。iPhone や Android の多くは広色域(Display P3)でも、**P3 のまま出すと変換で色が変わる**ことがある(⚪) |
| コントラスト | 文字と背景の比 **4.5:1 以上**(大きな文字は 3:1 以上)。屋外・低輝度でも読める |
| 背景色 | **真っ白(#FFFFFF)の大面積**はダークモードで眩しい。オフホワイトか有彩色を |
| 真っ黒(#000000) | OLED では暗部のつぶれ・黒浮きが目立つことがある。#111〜#1A1A1A 程度が安全(⚪) |
| 彩度 | 高彩度の赤・蛍光色は圧縮でノイズになりやすい |
| 細い線・細い文字 | 圧縮でつぶれる。線は 3px 以上、文字は太めのゴシック/明朝のウェイト 500 以上 |

## 7. 考察⑥: ファイルサイズと通信

- 4:5 の 1080×1350 JPEG は、品質 80〜85 で **約 150〜400KB** が目安(⚪)。写真が多いほど大きい。
- **PNG の写真・グラデーション**はサイズが大きくなり、再圧縮で劣化する。写真は JPEG。
- 各プラットフォームは**再圧縮**する。元画像を**上限ぎりぎりまで大きくしない**(上限の半分)。
- 通信が遅い環境では、読み込みが遅いと離脱する。

## 8. 結論(推奨セット)

| 用途 | サイズ | 備考 |
|---|---|---|
| **フィード画像(共通)** | **1080×1350(4:5)・JPEG・sRGB** | Instagram・Threads・X・Facebook に共通。本文 44px 以上 |
| 正方形 | 1080×1080 | プロフィール・商品 |
| 横長(リンクカード) | 1200×630 または 1280×670 | note の見出し 1280×670 ✅(約 1.91:1) |
| ストーリーズ/リール/ショート/TikTok | **1080×1920(9:16)** | 安全領域を空ける |
| YouTube 動画 | 1920×1080(16:9)、サムネイル 1280×720 以上(推奨 3840×2160) | サムネイル文字は 100px 以上 |
| YouTube Shorts | 1080×1920 | サムネイル 9:16 ✅ |
| X の動画 | 720p〜1080p(Premium は 1080p 可 ✅) | 縦なら 720×1280 |

## 9. 実機でのテスト手順

1. **iPhone と Android の実機**(できれば画面の小さい機種と大きい機種)で、公開前に下書き・限定公開で確認。
2. **ライトモードとダークモード**、**明るさ最小と最大**、**屋外**。
3. **最小の文字を、腕を伸ばした距離**で読めるか。
4. **グリッド/一覧のサムネイル**で主題が分かるか(Instagram のプロフィール、YouTube の一覧、X のタイムライン)。
5. **VoiceOver(iPhone)・TalkBack(Android)**で代替テキストを確認([alt-text](alt-text.md))。
6. **低速回線**(機内モードでキャッシュなし、Wi-Fi オフ)で読み込み時間を確認。
7. 結果を [image-checklist](../../templates/image-checklist.md) に反映。

## よくある失敗と対処

| 失敗 | 原因 | 対処 |
|---|---|---|
| パソコンでは読めた文字がスマホで小さい | 作業画面で拡大して見ていた | 書き出し後に**スマホ実機**で確認。本文 44px 以上(§4) |
| 縦動画の字幕がボタンやキャプションに隠れる | 安全領域を考えていない | 上 約10%・下 約15%・右 約15% を空ける(⚪) |
| 投稿後に色がくすむ・変わる | P3 や HDR のまま書き出した | sRGB・SDR で書き出す(§5・§6) |
| プロフィールのグリッドで何の投稿か分からない | 文字を詰め込みすぎた | グリッドでは主題を中央に1つだけ |
| 画像がぼやける | 小さな画像を拡大して使った、再圧縮が重なった | 幅 1080px 以上で作り、上限ぎりぎりの容量にしない |
| ダークモードで白背景がまぶしい | 真っ白の大面積 | オフホワイトや有彩色の背景にする |
