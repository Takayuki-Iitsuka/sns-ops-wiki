# 分析と KPI

> **このページで分かること**: SNS の数字(インサイト、アナリティクス)の読み方、目標に合う指標の選び方、記録と振り返りのやり方。
>
> **対象**: 初心者(数字をどう見ればよいか分からない人)  **先に読むページ**: [30-strategy/01-goals-kpi-roadmap](../30-strategy/01-goals-kpi-roadmap.md)(目標の立て方)

## 概要

SNS の管理画面には、表示回数・いいね・保存など多くの数字が並びます。全部を追うと「結局どうすればよいか」が分からなくなります。大事なのは次の順番です。

1. **目的を決める**(知ってもらいたい / 問い合わせを増やしたい / 売上につなげたい)。
2. **目的に合う指標を1〜3個だけ選ぶ**(これが KPI)。
3. **同じ条件で記録し、週1回振り返って次の投稿を変える**。

数字は「通知表」ではなく、**次に何を試すかを決める材料**です。

## 用語

| 用語 | 意味 |
|---|---|
| KPI / key performance indicator(重要業績評価指標) | 目標に近づいているかを測るために選んだ少数の指標 |
| impression(インプレッション、表示回数) | 投稿が画面に表示された回数。同じ人に2回表示されたら2回 |
| reach(リーチ) | 投稿を見た**人数**(重複を除く) |
| view(ビュー、再生・表示) | 動画の再生回数や投稿の表示回数。数え方はサービスごとに違う |
| engagement(エンゲージメント) | いいね・コメント・シェア・保存など、見た人の反応 |
| engagement rate(エンゲージメント率) | 反応の数 ÷ 表示回数(またはリーチ、フォロワー数)。分母はサービス・ツールで違う |
| save(保存) / bookmark(ブックマーク) | あとで見るために保存された数。「役に立った」のサイン |
| profile visit(プロフィールアクセス) | 投稿からプロフィールを見に来た数 |
| CTR / click-through rate(クリック率) | クリック数 ÷ 表示回数 |
| conversion(コンバージョン、成果) | 購入・登録など、最終的にしてほしい行動 |
| insights(インサイト) / analytics(アナリティクス) | 各サービスの分析画面の呼び名 |

## 指標の階層

| 段階 | 指標 | 見る目的 |
|---|---|---|
| 認知 | impression(表示回数)、reach(リーチ) | 届いているか |
| 関心 | エンゲージメント率、保存、プロフィールアクセス | 興味を持たれたか |
| 行動 | リンククリック、フォロー、問い合わせ | 次の行動をしたか |
| 成果 | 購入、メンバー登録、売上 | 収益に繋がったか |

## 原則

1. **目的に合う指標を1〜3個に絞る**(多すぎると判断できない)。
2. **絶対数より傾向と比率**を見る(フォロワー数に対するエンゲージメント率等)。
3. **同条件で比較**する(時間帯、形式、テーマを揃えて A/B)。
4. **週次レビュー**を習慣にする: [templates/weekly-review.md](../../templates/weekly-review.md)

## 手順: 目的から KPI を選ぶ

| 目的 | KPI の例(1〜3個) | 補助で見る指標 |
|---|---|---|
| まず知ってもらう | リーチ、新規フォロワー数 | 表示回数、シェア |
| 信頼を作る(役立つ情報) | 保存率(保存 ÷ リーチ)、プロフィールアクセス | コメント |
| 交流を増やす | コメント数、返信の往復数 | いいね |
| サイト・ショップへ誘導 | リンククリック数、CTR | プロフィールアクセス([link-in-bio-and-utm](link-in-bio-and-utm.md)) |
| 売上・登録 | コンバージョン数 | クリック数 |

### 週次の記録の手順(15〜30分)

1. 各サービスの分析画面を開く(場所はサービス別の `analytics` ページ: [X](../02-x/08-analytics.md) / [Instagram](../03-instagram/08-analytics.md) / [note](../04-note/08-analytics.md))。
2. 先週の投稿ごとに、KPI と「投稿の条件」(形式、柱、時間帯、タグの数)をスプレッドシートに写す。
3. 上位3本と下位3本を並べ、**条件の違い**を1行でメモする。
4. 次の週に試すことを**1つだけ**決める(例: 「1枚目に結論を書く」)。
5. 4週ごとに KPI の推移を見て、目標や柱を見直す([content-planning](content-planning.md))。

## 用語の定義はサービスで異なる

「リーチ」「インプレッション」の数え方はサービスごとに異なります。サービス間で単純に数値比較しない。定義は各 `08-analytics.md` で確認。

| サービス | 公式文書で確認できた定義・制約 | 確度 |
|---|---|---|
| Instagram(API) | `reach` は「少なくとも1回見た**ユニークな**ユーザー数」(推定値)。`impressions` は **2024年(皇紀2684年・令和6年)7月2日より後に作られた投稿では廃止**、代わりに `views` などを使う | ✅ Instagram Media Insights |
| X(API) | 表示回数(`impression_count`)などの公開指標と、URL クリック・プロフィールクリックなどの非公開指標がある。**非公開・オーガニック・プロモの指標は、作成から30日以内の投稿のみ取得可能** | ✅ docs.x.com Metrics |
| 各アプリの画面 | 指標名・集計期間はアプリの版で変わる | ⚪ |

> X の非公開指標は30日を過ぎると API で取れなくなるため、**毎週記録しておく**ことが大切です(✅ 上記の制約による)。

## 具体例

- **良い例**: 「保存率を KPI にした。図解カルーセルは保存率が高く、写真1枚は低い。来週は図解を1本増やす」
- **悪い例**: 「フォロワーが昨日より3人減った。投稿をやめよう」(1日の増減は誤差が大きい)
- **悪い例**: 「X のインプレッションが Instagram のリーチより多いから X のほうが良い」(定義が違うので比較できない)

## よくある失敗と対処

| 失敗 | 対処 |
|---|---|
| 指標を10個以上追ってしまう | KPI は1〜3個。他は「補助」として月1回だけ見る |
| 1本ごとの結果に一喜一憂 | 最低でも同じ条件の投稿を5本程度集めて傾向を見る(⚪) |
| 条件を記録していない | 形式・時間帯・柱を必ず一緒に記録する |
| 一度に3つ変える | 何が効いたか分からない。**1回に1つだけ変える** |
| 記録を後回しにして数字が消える | X の非公開指標は30日で取れなくなる(✅)。週次で記録 |

## 注意点

- 公開リポジトリには**実数を書かず**、比率・傾向のみ(→ [CONTRIBUTING](../../CONTRIBUTING.md))。スプレッドシート等の実データは非公開で管理します。
- フォロワー数を買う・相互フォローで水増しすると、エンゲージメント率が下がり判断を誤ります(⚪)。
- 分析画面の利用には、プロアカウント(ビジネス/クリエイター)への切り替えが必要なサービスがあります(各サービスのページで確認 ⚪)。

## 記録

スプレッドシート等に日次/週次で記録。公開リポジトリには**実数を書かず**、比率・傾向のみ。API で自動取得する方法は [20-api/10-benefits-of-api](../20-api/10-benefits-of-api.md)。
