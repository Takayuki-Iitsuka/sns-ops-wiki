# note のコツ(経験則 ⚪)

> **このページで分かること**: note を続けて読まれる場所にするための、入口づくり・記事の質・運用・収益の実践的なコツ。
>
> **対象**: 初心者〜中級者  **先に読むページ**: [02-posting](02-posting.md)

## 概要

このページのコツは、公式の仕様ではなく**多くの運用で共通する経験則(⚪)**です。
note は「記事が資産として残る」ため、1本ごとの完成度と、**記事どうしのつながり(導線)**が効いてきます。
全部を一度に実行する必要はありません。まず「入口づくり」の3つから始めてください。

## 用語

| 用語 | 意味 |
|---|---|
| 導線 | 読者が次の記事・マガジン・購入へ進む道筋 |
| 目次記事(まとめ記事) | 過去記事をテーマ別にリンクでまとめた記事 |
| シリーズ化 | 長いテーマを複数の記事に分けて連載すること |
| ストック型 | 公開後も長く読まれ続ける性質(反対はフロー型) |

## 入口づくり

1. **見出し画像とタイトルが入口**: 一覧と SNS 共有で最初に見られる。見出し画像は 1280×670 🟡([03-media-specs](03-media-specs.md))。
2. **目次記事(まとめ記事)**を作り、固定する。過去記事の導線が整う。
3. **「はじめに」記事**: 誰が・何を・どの順で読めばよいかを示す。

「はじめに」記事の構成例:

```
1. 自己紹介(3行)
2. このアカウントで読めること
3. 最初に読んでほしい記事3本(リンク)
4. 連載・マガジンの一覧
5. 更新日と連絡先
```

## 記事の質

4. **1記事1テーマ**。長すぎたらシリーズ化。
5. **出典を明示**: 参考文献・一次資料のリンクを示す。
6. **更新履歴**を記事末尾に。古い記事の誤りを直したら明記。
7. **公開後に読み直す**: 誤字・リンク・数値。
8. **具体例を必ず1つ入れる**: 抽象的な説明だけでは伝わりにくい。

## 運用

9. 更新頻度は無理のない範囲で固定(週1等)。
10. X・Instagram で告知し、note に詳細を置く([funnel](../30-strategy/02-funnel.md))。
11. 有料は成果物を明確に(手順・テンプレ・事例・図解)。
12. コメントから次の記事のテーマを拾う。
13. **ネタ帳**を作る: 質問・気づき・失敗をメモし、記事の種にする([企画づくり](../01-common/content-planning.md))。
14. 書きためて予約投稿を使うと、更新が途切れにくい(予約投稿は note プレミアムの機能とされる 🟡 [料金](../40-pricing/04-other-services.md))。

## 収益

15. 無料記事で信頼を作り、有料記事で成果物を提供。
16. メンバーシップは更新頻度と限定性を設計し、解約理由を減らす。
17. 手数料・価格の範囲は公式で確認してから設計(#5, #6)。現在の記載は [07-monetization](07-monetization.md)(🟡 プラットフォーム利用料 10% など [手数料](https://www.help-note.com/hc/ja/articles/360011358873))。

## 具体例: 1週間の運用リズム(⚪)

| 曜日 | やること |
|---|---|
| 月 | ネタ帳から次の記事を1つ選び、見出しだけ書く |
| 水 | 本文を書く |
| 金 | 見出し画像を作り、見直し |
| 土 | 公開・X で告知 |
| 日 | コメントに返信。翌週のネタをメモ |

## 避けること

- 出典のない数字の断定
- 他人の文章・画像の無断転載
- 煽りタイトルで中身が薄い有料記事
- 事実と解釈の混在(特に医療・お金・歴史・時事など誤解を招きやすい話題 → [正確さ](../01-common/sensitive-topics-and-accuracy.md))

## よくある失敗と対処

| 失敗 | 対処 |
|---|---|
| 最初から長文の大作を狙い、続かない | 短めの記事で頻度を優先し、後でまとめる |
| 記事どうしがつながっていない | 記事末尾に関連記事、目次記事を更新 |
| 告知を1回しかしない | 公開時+数日後に別の切り口で再告知(⚪) |
| 古い記事が誤ったまま | 定期的に見直し、更新履歴を書く |

## 注意点

- コツは経験則です。自分の数字([08-analytics](08-analytics.md))で効果を確かめてください。
- AI を使って書く場合は [AI 利用方針](../01-common/ai-usage-policy.md) を確認してください。
