# 読み方と確度ラベル

> **このページで分かること**: 各ページの構成、✅🟡⚪ の確度ラベルの意味、最終確認日(`last_verified`)の見方、情報が古いときの確かめ方。
>
> **対象**: すべての読者(最初に必ず読んでください)。**先に読むページ**: [はじめての SNS 運用](beginners-guide.md)

## 概要

SNS の仕様(文字数、画像サイズ、収益化の条件、料金など)は、数か月単位で変わります。このナレッジベースでは、**どの情報がどれくらい確かか**を一目で分かるように、すべての数値・条件に「確度ラベル」を付けています。ラベルの意味を知っておくと、「そのまま使ってよい情報」と「使う前に確認すべき情報」を見分けられます。

## 確度ラベル

| ラベル | 意味 | 扱い | 例 |
|---|---|---|---|
| ✅ | 公式ヘルプ・公式ブログ・規約・開発者文書・法令など**一次資料**で確認済み | そのまま利用可。ただし確認日を見る | 「キャプションは最大2,200字 ✅」 |
| 🟡 | 解説記事・ニュースなど**二次資料**のみで確認 | 実運用前に公式で確認 | 「上限が5個に変わったと報道 🟡」 |
| ⚪ | 一般的な知識・経験則。出典なし | 参考程度。公式で確認 | 「朝の投稿が見られやすいことが多い ⚪」 |

### 一次資料と二次資料の違い

- **一次資料**: その情報を決めた本人(サービスの運営会社、法令を作った国など)が出している資料。例: X の開発者文書、YouTube ヘルプ、消費者庁のページ。
- **二次資料**: 一次資料をもとに第三者が書いた解説や報道。分かりやすい反面、古い情報や誤解が混ざることがあります。

詳しくは [出典方針](source-policy.md) を見てください。

## ページの構成

多くのページは、[ページ雛形](page-template.md) に沿って次の順に並んでいます。

| 節 | 内容 |
|---|---|
| 先頭の front matter(`---` で囲まれた部分) | タイトル、最終確認日(`last_verified`)、ページ全体の確度(`confidence`)、主な出典(`sources`) |
| このページで分かること | 1〜3行の要約、対象読者、先に読むページ |
| 概要 | 何のための機能・考え方か |
| 用語 | そのページで出てくる専門用語 |
| 手順 / 仕様 | 具体的な操作や数値(表の「確度」「出典」列に注目) |
| 具体例・よくある失敗 | 実際の使い方と、つまずきやすい点 |
| 注意点・チェックリスト | 投稿前に確認すること |
| 関連ページ / 次に読む | 続けて読むと理解が深まるページ |
| 出典 | 使った資料の URL と確認日 |
| 変更履歴 | いつ何を変えたか |

### front matter の読み方

```yaml
---
title: Instagram 初期設定     # ページ名
platform: instagram          # 対象サービス(common は共通)
topic: setup                 # 分類(setup=初期設定、posting=投稿、media=画像・動画 など)
last_verified: 2026-11-03    # 最後に内容を確認した日
confidence: 🟡               # ページ全体の確度(主要な情報の確度)
sources:                     # 主な出典
  - https://example.com/help
---
```

## 情報の鮮度

- SNS の仕様・収益化条件は数か月で変わります。各ページの `last_verified`(最終確認日)を必ず確認してください。
- **6か月(180日)以上前**に確認された項目は「古い可能性」があるものとして扱い、再確認します。検査スクリプト(`scripts/check_wiki.py`)も 180日を超えたページに警告を出します。

### 情報が古いかもしれないときの確かめ方

1. ページ末尾の「出典」にある公式 URL を開きます。
2. 公式ページの数値とこのページの数値を比べます。
3. 違っていたら、公式の値を使ってください。可能なら、このナレッジベースの修正(または [要検証リスト](verification-queue.md) への追記)をお願いします。→ [編集規約](../../CONTRIBUTING.md)

## 年の書き方

このナレッジベースでは、年を「**西暦(皇紀・和暦)**」の形で書きます。例: 2026年(皇紀2686年・令和8年)。

- 皇紀(神武天皇即位紀元)= 西暦 + 660
- 令和 = 西暦 − 2018(2019年が令和元年)

front matter の日付は国際標準の ISO 8601 形式(`2026-11-03`)です。

## 本ナレッジベースの現状(重要)

2026年(皇紀2686年・令和8年)11月3日に、X(docs.x.com)、Instagram・Threads(developers.facebook.com)、YouTube ヘルプ、LINE 開発者文書、消費者庁は**本文を直接取得して ✅ に更新**しました。同日の全ページ加筆でも、各ページの担当範囲で公式資料を追加確認しています。

一方、`help.x.com`・`www.help-note.com` は bot 確認、`help.instagram.com` は JavaScript 描画で本文を取得できないことが多く、**🟡(検索要約・二次資料)や ⚪(一般知識)が残っています**。取得状況と手順は [verification-queue.md](verification-queue.md) を参照してください。

## よくある質問

| 質問 | 回答 |
|---|---|
| ⚪ の情報は使ってはいけないの? | 使ってかまいませんが、「確かめていない情報」として扱ってください。重要な判断(お金・契約・規約)には使わず、公式で確認してください |
| ✅ なら絶対に正しい? | 確認日の時点では公式と一致していました。その後に変わっている可能性はあります |
| ラベルが付いていない文は? | 考え方・手順の説明など、数値や条件を含まない文です |
