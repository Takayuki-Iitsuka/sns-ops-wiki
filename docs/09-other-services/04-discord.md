# Discord

> **サーバー(Server)**という招待制のコミュニティ空間で、チャット・音声・フォーラム・配信を行うサービス。SNS の「広く届ける」役ではなく、**既存ファンを集めて深くつながる場**として使います。
> **取得状況**: `discord.com`・`support.discord.com`・`creator-support.discord.com` は本セッションのネットワーク制限で**取得できませんでした**。数値は検索要約(🟡)と一般知識(⚪)で、**公式での確認が必要**です(#62〜#66)。

## 1. 位置づけ(⚪)

| 項目 | 内容 |
|---|---|
| 主な形式 | テキストチャンネル、ボイスチャンネル、フォーラム、アナウンス、ステージ、イベント |
| 強み | 双方向の交流、常連の定着、限定コンテンツ、ボット/Webhook による自動化 |
| 弱み | 発見されにくい(検索・拡散向きではない)、運営(モデレーション)の負荷が高い |
| 向く用途 | ファンの居場所、制作の裏側共有、質問対応、配信・更新の通知、有料メンバー向けの場 |
| SNS との関係 | X・YouTube・Instagram で認知 → **招待リンクで Discord へ** → メンバー化([funnel](../30-strategy/02-funnel.md)) |

## 2. サーバーの構成(⚪)

| 要素 | 内容 | 運用の目安 |
|---|---|---|
| チャンネル | テキスト / ボイス / フォーラム / アナウンス / ステージ | 最初は少なく(ルール・お知らせ・雑談・質問・作品)。増やしすぎない |
| カテゴリ | チャンネルのグループ | 役割ごと(案内、交流、メンバー限定) |
| ロール(Role) | 権限と見た目のグループ | 管理者・モデレーター・メンバー・有料メンバーを分ける |
| アナウンスチャンネル | 他サーバーから「フォロー」されて配信できる | お知らせの再配信に使える |
| フォーラム | 話題ごとのスレッド形式 | 質問・作品共有・要望の整理に向く |
| イベント | 日時付きの予定(ボイス・外部リンク) | 配信・読書会・相談会の告知 |
| コミュニティ機能 | サーバーを「コミュニティ」にすると、ルール確認画面、オンボーディング、ウェルカム画面、アナウンス、ディスカバリー(条件あり)などが使える | 有料化にも必要とされる資料あり(#62) |

## 3. 初期設定の手順(⚪)

1. サーバーを作成(テンプレートから始められる)。
2. **ルールチャンネル**を作る(禁止事項、通報先、モデレーション方針)。
3. ロールと権限を設計(**一般メンバーに管理権限を与えない**)。
4. 認証レベル(Verification Level)とセーフティの設定(スパム・不審アカウント対策)。
5. **AutoMod**(禁止語・スパム・メンション爆撃の自動検知)を有効化。
6. 管理者・モデレーターは**二要素認証(2FA)**を有効化([account-security](../01-common/account-security.md))。
7. 招待リンクは**有効期限・使用回数**を設定して発行(永久リンクの拡散を避ける)。
8. コミュニティ機能・オンボーディング(参加時の質問でロールを付与)を設定。

## 4. 画像・ファイル仕様(⚪ #64)

| 項目 | 目安 | 確度 |
|---|---|---|
| サーバーアイコン | 512×512 px 推奨(最小 128×128 程度) | ⚪ |
| サーバーバナー | 960×540 px(16:9) 。**ブーストのレベルが必要** | ⚪ |
| 招待の背景(Invite Splash) | 1920×1080 px。ブーストのレベルが必要 | ⚪ |
| カスタム絵文字 | 128×128 px、256KB 以内 | ⚪ |
| ステッカー | 320×320 px、512KB 以内 | ⚪ |
| 添付ファイルの容量 | 無料ユーザーは **10MB 前後**、Nitro は大きい。ブースト段階でサーバー全体の上限が上がる。**現行値は要確認** | ⚪ |
| ブースト(Server Boost) | 段階(レベル 1〜3)に応じて絵文字枠・音質・アップロード上限・バナー等が増える。必要ブースト数は要確認 | ⚪ |

> 画像・動画は他の SNS 向けの書き出し([export-presets](../01-common/export-presets.md))をそのまま貼れるが、**容量上限が小さい**ので、動画は YouTube の限定公開などに置いてリンクを貼るのが無難(⚪)。

## 5. 収益化(🟡 不一致あり)

| 手段 | 内容 | 確度 |
|---|---|---|
| **Server Subscriptions** | サーバーの有料メンバーシップ(月額)。特典ロール・限定チャンネル | 🟡 |
| 手数料 | デスクトップ/ブラウザ決済は**プラットフォーム手数料 10%**(決済手数料・取引手数料・税の後に計算)とする資料が複数。iOS/Android のアプリ内購入は別途ストア手数料(Apple 30% とする資料) | 🟡 #63 |
| 資格要件 | 18歳以上、コミュニティ有効化、**サーバー作成から 30日以上**、メンバー数 500人(2026年に 1,000人から引き下げとする資料。**不一致**) | 🟡 #62 |
| 対象国 | 米国・英国・カナダ・豪州・EU の多くなどとする資料、米国のみとする資料。**日本の提供は未確認** | 🟡 #62 |
| 支払い | 初回の払い出しは最低 $100 とする資料が 1つ | 🟡 #63 |
| 価格 | 月額 $2.99〜$199.99 の設定とする報道(2022年ごろ) | 🟡 |
| Premium Apps | **開発者**がボット/アプリ内のサブスク・単発商品を販売。手数料 15% または 30% とする資料 | 🟡 #63 |
| 規約 | 「Server Monetization Policy」(サーバー収益化ポリシー)に従う | 🟡 #66 |

- 公式の最新条件が確認できるまでは、**「日本で、自分のサーバーが条件を満たすか」を Discord の画面(サーバー設定の収益化)で確認**する。
- 日本で Server Subscriptions が使えない場合の代替: **外部の課金サービス**で支払い(FANBOX・Fantia・Patreon・note メンバーシップなど [01-fan-club](../10-creator-economy/01-fan-club.md))→ 支払い済みの人に**手動またはボットでロール付与**する運用。この場合 **Discord の外での課金**になるため、規約・返金・個人情報の扱いに注意(⚪)。
- 継続収入は所得。海外プラットフォームからの入金の扱いは [tax-and-business](../30-strategy/04-tax-and-business.md)。

## 6. 運用(⚪)

| テーマ | 目安 |
|---|---|
| 立ち上げ | 最初の 20〜50人は**既存ファンを個別に招待**。人がいない空のチャンネルを増やさない |
| 活性化 | 週間イベント(雑談会、作業会、配信後の感想)、質問への回答日を固定 |
| ルール | 「禁止事項」「通報方法」「モデレーターの権限」を明文化。違反時の対応を一貫させる |
| モデレーション | 複数人体制。ログチャンネルで操作を記録。荒らしは即時ミュートとバン |
| 子ども | Discord の利用は一定年齢以上(13歳以上が基本とされる ⚪ #66)。未成年に配慮し、**DM での個別連絡や個人情報の収集を避ける** |
| 通知疲れ | `@everyone` の多用を避ける。通知はお知らせチャンネルに集約 |
| 離脱対策 | 定期的にチャンネルを整理し、使われていないものは閉じる |

## 7. 他サービスとの連携(⚪)

| やりたいこと | 方法 |
|---|---|
| YouTube/X の新着を通知 | RSS+Webhook、または既存のボット(自作せず公式連携や信頼できるボットを使う) |
| ライブ配信の開始を通知 | Twitch/YouTube の連携機能やボット |
| 投稿計画の共有(チーム) | 非公開チャンネル。**公開前の案や個人情報を public な場所に置かない** |
| 問い合わせの受付 | フォーラム/専用チャンネル。個人情報はやり取りしない |

## 8. API・Webhook(⚪ 公式は未取得 #65)

| 項目 | 内容 | 確度 |
|---|---|---|
| Webhook | チャンネルごとに URL を発行し、HTTP POST で投稿できる。**URL 自体が秘密**(漏れると誰でも投稿できる) | ⚪ |
| Webhook 本文の上限 | `content` は 2,000 文字。埋め込み(embed)は 1 メッセージに最大 10 個、合計 6,000 文字程度 | ⚪ |
| ボット | Bot Token で Gateway(WebSocket)と REST API を使う。**トークンは秘密情報**(リポジトリに書かない) | ⚪ |
| 特権インテント | メッセージ内容の取得(Message Content Intent)などは**申請・有効化が必要**(大規模ボットは審査) | ⚪ |
| レート制限 | REST に全体と個別の制限があり、超えると 429。無効なリクエストが多いと一時的にブロックされる。**レスポンスヘッダーを見て待つ** | ⚪ |
| 利用者トークン | 一般ユーザーの自動化(セルフボット)は**規約違反**でアカウント停止の対象 | ⚪ |
| 料金 | 公式のボット/Webhook の API 利用料は確認していない。Premium Apps の販売時は手数料(#63) | ⚪ |

- 通知だけなら **Webhook が最も簡単で安全**(トークン管理が不要で、権限が小さい)。
- 詳しい自動化の方針: [20-api/01-concepts-and-security](../20-api/01-concepts-and-security.md)、[11-tool-integrations](../20-api/11-tool-integrations.md)。

## 9. 注意点

- **Discord 内での勧誘・案件・アフィリエイト**も広告表記が必要([legal-compliance](../01-common/legal-compliance.md))。
- 有料メンバー向けコンテンツの**二次配布の禁止**をルールに明記(スクリーンショットの転載など)。
- メンバーの個人情報・発言の外部利用は、事前の同意を取る([privacy-and-personal-info](../01-common/privacy-and-personal-info.md))。
- 炎上・トラブル時の対応は [crisis-response](../01-common/crisis-response.md)。
- 有料化すると**運営の責任が増える**(返金・特典の履行・規約)。無料で定着してから検討するのが安全(⚪)。
